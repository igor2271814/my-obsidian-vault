Типы методологий:
1. **Тяжеловесные**
	1. Один из примеров, который все еще местами используется - **водопадная методология**. Работает только последовательно, находясь на стадии n + 1 нельзя внести изменения в стадию n или откатиться до этой стадии. Из-за этого в методологию внедряют **ОГРОМНЫЙ** документооборот, жесткий контроль и надзор для исключения любых возможных ошибок![[Pasted image 20260218135552.png]]![[Pasted image 20260218135706.png]]
2. **Легковесные** - добавляют больше адаптивности и возможностей для тестирования. Подразумевают постоянные проверки, тесты и т.д. Нацелены на менее крупные системы (на небольшие организации)

Методологии можно классифицировать по различным критериям, например по виду. весу. направлению деятельности, кол-ву участников. **Основной метод - по весу**

Примеры классификации по весу:
 1. Тяжеловесные
	 1. **ГОСТ 19 "Единая система программной документации"** и **ГОСТ 34 "Стандарты на разработку и сопровождение автоматизированных систем"** ориентированы на последовательный подход к разработке программного обеспечения
	 2. **Copability Maturity Model of Software (SW - CMM)** определяет пять уровней "зрелости проекта"
	 3. **Rational Unified Process (RUP)** - итеративная модель разработки
	 4. **Microsoft Solution Framework (MSF)** - база знаний компании Microsoft по разработке программ
	 5. **Personal Software Process** - модель определяет требования к компетенциям разработчика. **Team Software Process** - модель ориентирует на самоуправляемые команды от 3 до 20 разработчиков
	 6. и д.р.
2. Легковесные
	1. **eXtreme Programming или XP** - экстремальное программирование, предлагающее 12 инженерных практик
	2. **Crystal Clear** - семейство методологий, определяют необходимую степень формализации процесса разработки в зависимости от количества участников и критичности задач
	3. **OpenUP** - итеративно-инкрементальный метод разработки программ, позиционируется как легкий и гибкий вариант тяжеловесной методологии RUP
	4. **Scrum** - управление разработкой информационных систем с высокой степенью неопределенности
	5. **Kanban** - методология "бережливого производства"
	6. и д.р.

## Определение (или почему у нас куча одинаковых по сути предметов)

	Программный проект - временное предприятие, предназначенное для создания уникальных продуктов, услуг или результатов
	
	Программная инженерия (инженерия программного обеспечения) - система инженерных принципов для создания экономичного ПО, которое надежно и эффективно работает в реальных компьютерах (1968)
	
	Международный терминолоический стандарт ISO/IEC 2382/1-93:
		Программная инженерия - систематическое применение научных и технологических знаний, методов и практического опыта к проектирвоанию, реализации, тестировании и документирования ПО в целях оптимизации его производства, поддержки, качества

Методы программной инженерии обеспечивают решение широкого спектра технических задач разработки:
1. Планирование и оценка программного проекта
2. Анализ требований к компьютерной системе в цело и к ПО в частности
3. Проектирование структур программ (и структур данных), входящих в состав ПО
4. Конструирование программного текста (кодирование, программирование, реализация)
5. Тестирование
6. Сопровождение ПО

Официальная классификация процессов программной инженерии
* Международный стандарт ISO/IEC 12207-2008
* Российский стандарт ГОСТ Р ИСО/МЭК 12207-2010

1. Процессы соглашения
2. Процессы организационного обеспечения проекта - **на предмете будем заниматься этим**
3. Процессы проекта
4. Технические процессы

### Процессы проекта

1. Процессы менеджмента проекта используются для планирования, выполнения, оценки и управления продвижения проекта
2. Процессы поддержки проекта обеспечивают выполнение специализированных целей менеджмента
* процесс менеджмента решений
* процесс менеджмента рисков
* процесс менеджмента конфигураций
* процесс менеджмента информации
* процесс измерения

**Базис процессов разработки ПО:**
1. Подготовка
2. Планирование
3. Моделирование
4. Конструирование
5. Развертывание
