## Сетевые модели (Уровни моделей OSI)
![[Pasted image 20250909100345.png]]
**Физический уровень** - определяет метод передачи данных и среду использования
**Канальный уровень** - обеспечивает выполнения многих ф-ций. Адресация, проверка ошибок, целостности (МАКи)
**Сетевой уровень** - обеспечивает процедурные и функциональные средства для передачи данных между объектами. Рассматривает оптимальные маршруты
Эти три уровня - основа сетей или базовая сетевая технология
**Транспортный уровень** - порты, нужные для указания назначения конкретной службы
Остальные уровни - прикладные. Обеспечивают работу на хостах
**Сеансовый уровень** - используется для логического взаимодействия между приложениями
**Представительский уровень** - обеспечивает согласования формата данных, обрабатываемые приложениями
**Прикладной уровень** - обеспечивает прикладным приложениям доступ к OSI

## Метод доступа CSMA/CD
	В сетях Ethernet используется метод доступа к среде передачи данных, называемый методом коллективного доступа с опознаванием несущей и обнаружением коллизий

	Этот метод применяется исключительно в сетях с логической общей шиной (к которым относятся и радиосети, породившие этот метод). Все компьютеры такой сети имеют непосредственный доступ к общей шине
## Структура IP пакета

## Протокол TCP - протокол надежной доставки

Протокол IP не может обеспечить надежную передачу данных, поэтому используется TCP для обеспечения надежного канала обмена данными. Он относится к транспортному уровню. Работает **над протоколом IP**, использует потенциально ненадежный ip для транспортировки своих блоков. **Надежность** обеспечивается за счет установления логических соединений

Протокол IP используется TCP как транспортное средство. Перед отправкой своих блоков TCP помещает их в оболочку IP пакета и при необходимости IP фрагментирует данные

## VLAN
Дословно - виртуальная локальная сеть - это группа устройств, имеющих возможность взаимодействовать между собой напрямую на канальном уровне, хотя физически при этом они могут быть подключены к разным сетевым коммутаторам. Логическая топология не зависит от физической. Как правило один влан - одна подсеть
**Основные преимущества:**
- Помогают структурировать сеть
- Используются для обеспечения безопасности
- Используют для объединения
- Уменьшают количество широковещательного трафика

### Тегирование
Тег это пометка, которая помещается внутрь кадра. Чтобы коммутатор мог различать трафик используется кадр, внутрь которого помещается тег. Данный тег должен говорит к какому влану принадлежит трафик

Распространённый и открытый стандарт 802.1Q - **открытый**. У Cisco свой **проприетарный** - ASL
![[Pasted image 20250909150111.png]]
Наиболее важное поле - VID (VLAN ID) - 12 бит. Это поле указывает к какому влану принадлежит трафик
По умолчанию тегирование не используется и присваивается VLAN - 1
Порт может быть в режиме: 
- ACCESS - порт доступа
- TRUNK - для взаимодействия порта между сетевыми устройствами
### Пример использования тегов
![[Pasted image 20250909151045.png]]
Порт доступа назначается в конечное подключенное устройство. А сами устройства не знают, что такое теги потому этим занимаются коммутаторы
Например с конечного хоста идет пакет на порт. Допустим влан будет 2. В этот кадр вкладывается тег, с указанием второго влана и он перемещается по адресу назначения. Если адрес назначения находится в этом коммутаторе, то тег не присваивается, он идет сразу в адрес назначения. Если он идет в другой коммутатор, то он идет на TRUNK порт, перемещается на другой коммутатор, тот сверяет данный тег и по своей таблице коммутации направляет его в тот порт, который относится ко второму влану. На этом порту удаляется тег и кадр отправляется на конечный хост

VLAN позволяет коммутаторам пересылать кадры по одному каналу - магистрали - TRUNK. Это делается путем добавления дополнительного заголовка (тег)
## Межвлановая маршрутизация
Нужна для перемещения пакетов между вланами. Осуществляется маршрутизаторами либо L3 коммутаторами
Существуют разные виды:
- **Традиционная** - для каждого влана используется отдельный порт устройства третьего уровня. Достаточно дорогой и не самый удобный способ![[Pasted image 20250909152341.png]]
- **Router on a stick** - на порт маршрутизатора настраиваются Саб интерфейсы (программный вириальный интерфейс который назначается над физическим), которые будут принадлежать разным вланам и иметь разные ip адреса. Недостаток - использование всеми саб интерфейсами одну полосу пропускания физического интерфейса. Теоретически возможно перенасыщение канала при большом кол-ве хостов. Но этот метод экономит порты ![[Pasted image 20250909153144.png]]
- **С использованием L3 коммутатора** - для каждого влана на коммутаторе (S2) выделяется отдельный порт для подключения к устройству третьего уровня. Порт работает в режиме доступа (ACCESS) и ему назначается конкретный влан. Каждый интерфейс маршрутизатора (R1) принадлежит своему влану и физический интерфейс маршрутизатора имеет свой ip адрес. ip на интерфейсе маршрутизатора (R1) будет являться шлюзом по умолчанию. Работает за счет виртуальных интерфейсов коммутатора (SVI) - обеспечивает обработку пакетов третьего уровня![[Pasted image 20250909153548.png]]
