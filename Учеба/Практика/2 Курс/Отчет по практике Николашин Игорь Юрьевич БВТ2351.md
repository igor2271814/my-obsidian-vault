# Индивидуальное задание

**Тема:**

Разработка клиентского веб-приложения для онлайн-бронирования билетов в кинотеатр.

**Цель:**

Создать прототип веб-приложения, позволяющего пользователю выбирать кинотеатры, фильмы, сеансы и места, а также просматривать информацию о них. Приложение должно быть реализовано с использованием HTML, CSS (SCSS), JavaScript без использования фреймворков. Данные должны храниться локально (localStorage или JSON).

**Функционал:**

1.    Просмотр афиши (кинотеатры, фильмы, сеансы). Выбор места в зале.

2.    Оформление брони.

**Технологии****:**

1.    Frontend: HTML, SCSS, Vanilla JS.

2.    Хранение данных: LocalStorage

  

# Введение

В современных условиях веб-технологии играют важную роль в организации сервисов развлечений, в том числе онлайн-продажи билетов в кино. **Актуальность** проекта состоит в востребованности удобных интернет-сервисов для выбора киносеансов и бронирования мест, особенно при удалённом режиме работы или ограничениях посещения кинотеатров.

**Цель работы** – разработать интерактивное веб-приложение для выбора кинотеатра, просмотра фильмов с возможностью фильтрации по жанрам и выбора мест на сеансы. **Задачи включают** анализ аналогичных систем, проектирование структуры приложения, реализацию интерфейса и логики на HTML/SCSS/JavaScript с использованием localStorage, а также тестирование и оформление практического отчёта.

**Анализ аналогов.** Существуют коммерческие системы онлайн-бронирования кинобилетов (официальные сайты кинотеатров, агрегаторы афиш, приложения киноактивности). Обычно они базируются на серверных технологиях и БД, обладают сложным интерфейсом. В отличие от них, разрабатываемое решение – статическое веб-приложение, в котором данные хранятся в локальных JSON-файлах и в хранилище браузера. Это упрощает развертывание и демонстрацию функциональности без задействования серверной части.

**Выбор технологий.** Для реализации проекта выбраны: HTML5 для разметки страниц, SCSS (Sass) – препроцессор CSS для удобства стилизации с переменными и модулями, JavaScript (ES6+) – для динамической логики, загрузки данных, фильтрации и управления состоянием. Для хранения пользовательских данных (выбранного кинотеатра и забронированных мест) используется Web Storage API – localStorage. Сравнение используемых технологий и причин выбора приведено в таблице ниже:

# Раздел 1. Общая характеристика разработки

## 1.1 Объект и предмет разработки

**Объект разработки** – система онлайн-бронирования кинофильмов. **Предмет разработки** – веб-приложение на HTML/SCSS/JS, реализующее функционал выбора кинотеатра, просмотра фильмов (с возможностью фильтрации) и бронирования мест. Ссылка на страницу - [https://igor2271814.github.io/cinema-booking/index.html](https://igor2271814.github.io/cinema-booking/index.html)

## 1.2 Структура проекта

Проект состоит из трёх HTML-страниц и сопутствующих ресурсов:

- **index.html** – главная страница. Содержит шапку (header) с навигационной ссылкой на выбор кинотеатра, переключатель темы (светлая/тёмная). Основной контент – карусель (слайдер) рекламных баннеров (itc-slider). При загрузке страницы может отображаться модальное приветствие. Футер страницы – контакты кинотеатра (см. Приложение А.1).
- **cinema.html** – страница выбора кинотеатра. Заголовок и список карточек кинотеатров. Данные о кинотеатрах загружаются из cinemas.json через fetch, рендерятся в контейнер #cinema-list. Каждая карточка при клике сохраняет выбранный кинотеатр в localStorage и переводит на страницу фильмов. Шаблон HTML карточки приведён в Приложении B.1.
- **cinema-and-movies.html** – страница деталей выбранного кинотеатра и списка фильмов. Здесь на основе сохранённого в localStorage объекта selectedCinema показываются детали (имя, адрес и т.д.) и список доступных фильмов этого кинотеатра. Фильмы загружаются из data.json (по id кинотеатра) и отображаются в сетке. Реализована фильтрация по жанрам (на странице кнопки или чекбоксы жанров). Для каждого фильма формируется карточка с постером и кнопкой, открывающей модальное окно сеансов и выбора мест.

Кроме страниц, проект включает файлы:

- **data.json** – JSON с данными о фильмах (массивы объектов с полями id, title, poster, sessions, genre). Пример структуры JSON см. Приложение А.2.
- **cinemas.json** – JSON с данными о кинотеатрах (название, адрес, изображение и т.п.).
- **script.js** – основной скрипт. Содержит логику загрузки JSON, рендеринга карточек кинотеатров/фильмов, обработчики событий (например, сохранение в localStorage, открытие модалок, выбор мест и запись брони). Фрагменты кода приведены в Приложении B.
- **itc-slider.js и itc-slider.css** – внешняя библиотека слайдера Она используется для реализации слайдера на главной странице, упоминается в отчёте (пакет не изменялся, код смотреть не нужно).
- **SCSS-структура**: главный файл style.scss собирает модули из папки block/. Там содержатся частичные файлы стилей: _header.scss, _footer.scss, _movies-grid.scss, _modal.scss, _seats.scss и др. Общие переменные (цвета, шрифты, отступы) вынесены в _variables.scss. С помощью расширения для VS Code «**Live Sass Compiler**» всё компилируется в единый style.css.

## 1.3 Страницы и логика взаимодействия

Пользовательский сценарий прост: с главной страницы переходим к выбору кинотеатра, затем видим фильмы и сеансы.

- **Выбор кинотеатра (cinema.html)**: при клике на карточку кинотеатра функция renderCinemas() из script.js выполняет localStorage.setItem('selectedCinema', JSON.stringify(cinema)), после чего через window.location.href происходит переход на cinema-and-movies.html.
- **Загрузка списка фильмов**: на странице фильмов код на DOMContentLoaded проверяет localStorage (см. Приложение B.2): если есть сохранённый кинотеатр, выполняется loadMoviesData() (fetch data.json) и renderMovies(). Иначе – уведомление об ошибке.
- **Фильтрация фильмов**: В UI реализован выбор жанра. При выборе жанра вызывается функция renderMovies(genre), которая отбирает из массива state.moviesData.movies только фильмы с полем genre === выбранный_жанр (используется Array.filter). Если жанр "all", показываются все фильмы. Пустой результат обрабатывается сообщением «Фильмов не найдено».
- **Модальное окно сеансов**: при клике на карточку фильма вызывается openModal(movie). Внутри создаются кнопки сеансов session-btn для каждого времени из массива movie.sessions, и вешается обработчик на клик – showSeatsSelection(movie, session). Это открывает модальное окно выбора мест.
- **Выбор мест и бронь**: Функция renderSeats() динамически генерирует сетку (8×8) дивов div.seat, для каждого рассчитывается уникальный id ряда и места (row-seat). Проверяется, занято ли место – если совпадает с уже забронированными (смотрим state.bookings в localStorage). При клике на незанятое место (обработчик toggleSeatSelection) добавляется/удаляется CSS-класс selected, а в состоянии state.selectedSeats сохраняются выбранные места. Кнопка «Забронировать» активируется только если есть выбранные места (disabled меняется через updateBookingButton). При подтверждении брони (bookSeats()), в state.bookings добавляется объект с информацией о брони и записывается в localStorage. Пользователь видит alert с подтверждением, модальное окно закрывается, а сетка мест обновляется (занятые помечаются).

Во всех местах, где код заимствует или сохраняет данные, есть ссылки на «Приложение» с листингом соответствующего кода (см. Приложение B.1–B.2).

  

# Раздел 2. Реализация функционала

## 2.1 Загрузка и фильтрация данных

**Загрузка данных**. Для кинотеатров и фильмов используются JSON-файлы. В script.js функции loadCinemasData() и loadMoviesData() реализуют fetch('cinemas.json') и fetch('data.json') соответственно. Подход с Fetch API предпочтителен: как отмечает MDN, fetch() возвращает Promise, результатом которого является Response, из которого через response.json() можно получить объекты JavaScript. Это позволяет асинхронно запрашивать данные и обрабатывать их без дополнительных библиотек.

**Отображение карточек**. После загрузки данных выполняются функции renderCinemas() и renderMovies(). Они сначала очищают контейнер (innerHTML = ''), а затем перебирают полученные объекты. Например, в renderMovies(genre) формируется массив moviesToShow:

    const moviesToShow = genre === 'all'

        ? state.moviesData.movies

        : state.moviesData.movies.filter(movie => movie.genre === genre);

(код из Приложения B.1). Затем создаётся HTML-контент каждой карточки через document.createElement('div') и innerHTML = .... В карточку вставляются изображение (<img> с атрибутом src на movie.poster и alt-текстом) и текстовые элементы. Обработчик события click добавляет открытие модального окна с сеансами или переходит к выбору фильмов (для renderCinemas()).

**Фильтрация по жанру**. UI предоставляет выбор жанров (например, выпадающий список или отдельные кнопки с жанрами). При изменении жанра вызывается renderMovies(новыйЖанр). Приведённый выше код с filter отбирает фильмы по совпадению поля genre. Этот простой способ работает быстро для небольших списков. Фильтрация выполняется на клиенте, что устраняет необходимость дополнительных запросов к серверу. После фильтрации, если список пуст, на экран выводится сообщение '<p class="no-movies">Фильмов не найдено</p>' (см. Приложение B.1).

**Кодовой пример (Фильтрация)**

    const moviesToShow = genre === 'all'

        ? state.moviesData.movies

        : state.moviesData.movies.filter(movie => movie.genre === genre);

_Примечание: полный код функции renderMovies – см. Приложение B.1. Здесь иллюстрируется ключевая логика отбора по жанру._

## 2.2 Логика выбора мест и localStorage

**Генерация сетки мест.** Функция renderSeats() динамически создаёт фиксированное количество рядов и мест в каждом ряду (например, 8×8). Для каждой создаётся элемент div с классом seat и атрибутом data-id («ряд-место»). Перед отображением проверяется, занято ли место: в state.bookings хранится массив ранее сделанных бронирований (из localStorage). Условие: если среди bookings найдётся бронь, где booking.movie === state.selectedMovie.title, booking.session === state.selectedSession и в её seats есть текущий seatId, то диву добавляется класс occupied. Таким образом уже занятые места помечаются визуально и недоступны для выбора.

**Выбор/отменa места.** На каждый «свободный» div.seat навешивается обработчик click, который вызывает toggleSeatSelection(seat). Эта функция проверяет, есть ли у seat класс occupied – если да, место игнорируется. Иначе у элемента переключается класс selected. Далее идентификатор места добавляется или удаляется из массива state.selectedSeats (см. Приложение B.1: при нажатии класс selected задаётся или убирается, а состояние массив selectedSeats обновляется). Затем кнопка бронирования обновляет своё состояние: если выбрано хотя бы одно место, она активна и показывает число выбранных мест, иначе остаётся неактивной.

**Подтверждение бронирования.** При клике на кнопку «Забронировать» вызывается функция bookSeats(). В ней формируется объект booking с полями: название фильма, сеанс, массив мест, текущая дата, жанр. Этот объект добавляется в глобальный массив state.bookings, который затем сериализуется и сохраняется в localStorage под ключом "bookings". Код:

state.bookings.push(booking);

  localStorage.setItem('bookings', JSON.stringify(state.bookings));

После сохранения выводится alert с подтверждением (название фильма, время и места), закрывается модальное окно, а сетка мест обновляется (renderSeats()). Таким образом информация о бронях сохраняется между перезагрузками страницы и даже после закрытия браузера.

**Использование localStorage.** В проекте localStorage применяется для: выбранного кинотеатра (selectedCinema), списка бронирований (bookings), и для темы оформления (dark mode). По умолчанию тема светлая, но при переключении сохраняется флаг localStorage.setItem('darkMode', ...) (см. toggleTheme()). MDN подчёркивает, что localStorage сохраняет данные между сессиями браузера, что подтверждает применимость этого метода хранения. Использование localStorage вместо серверной БД упрощает проект: всё хранение происходит на стороне клиента.

## 2.3 Структура SCSS и модульность стилей

Главный файл стилей – style.scss. Он собирает все частичные файлы (partials) из папки block/. Каждый частичный файл отвечает за отдельный компонент страницы:

- _header.scss, _footer.scss – стили для шапки и подвала.
- _modal.scss – оформление модальных окон (сеансы, выбор мест, промо-модалка).
- _movies-grid.scss – стиль сетки карточек фильмов.
- _seats.scss – стили сетки мест в кинозале.
- _buttons.scss, _body.scss – общие стили кнопок и тела документа.
- _variables.scss – набор переменных (цвета, отступы, шрифты).

Такой подход (модульных файлов) улучшает читаемость кода, позволяет работать разным разработчикам над разными файлами, а также легко повторно использовать и обновлять стили. Переменные SCSS хранятся в _variables.scss, что соответствует хорошей практике: Sass-переменные компилируются в конечный CSS, и их использование снижает дублирование кода. Например, цвет акцентов и базовые шрифты указаны однократно в переменных, затем применяются в стилях компонентов.

Для адаптивности макета (раздел 3) в SCSS применены медиавыражения (@media). Как отмечает MDN, «медиавыражения позволяют адаптировать страницу для различных типов устройств…». В проекте настроены брейкпоинты, реагирующие на ширину экрана, чтобы подогнать расположение элементов под мобильные и десктопные экраны. Например, меню навигации и сетка фильмов переходит из нескольких колонок в одну при узком экране.

## 2.4 Сценарии тестирования

Для проверки работы приложения выполняются следующие тесты:

- **Работоспособность навигации.** При загрузке index.html проверяем правильную работу слайдера и модалки. Кликаем на пункт меню «Кинотеатры» – происходит переход на cinema.html.
- **Загрузка данных и отображение кинотеатров.** Убедиться, что на cinema.html все записи из cinemas.json появились в виде карточек с изображениями и названиями. При отсутствии файла или ошибки fetch должен быть вывод в консоль (см. обработку ошибок в loadCinemasData).
- **Выбор кинотеатра.** Нажимаем на любую карточку – проверяем, что срабатывает localStorage.setItem('selectedCinema') и происходит переход на cinema-and-movies.html.
- **Фильтрация фильмов.** На странице фильмов проверяем фильтр: выбираем жанр «драма», удостоверяемся, что выводятся только фильмы жанра «драма» из JSON. При выборе несуществующего жанра – отображается сообщение «Фильмов не найдено» (например, если в тестовом данных нет фильмов этого жанра).
- **Выбор и бронирование мест.** На странице фильма кликаем на сеанс – открывается окно выбора мест. При попытке выбрать уже занятое место (имитируем ранее сделанную бронь, записав вручную в localStorage) – место должно быть отмечено и недоступно (.occupied). Выбираем несколько мест и жмём «Забронировать» – ожидается alert с правильной информацией и обновление состояния (места из селекта добавляются в занятые). Перезагружаем страницу и снова открываем тот же фильм/сеанс – выбранные ранее места должны остаться занятыми, т.к. данные в localStorage не потерялись.
- **Тесты на UI/UX.** Проверяем корректную смену темы (светлая/тёмная) с сохранением в localStorage. Тестируем адаптивность: изменяем размер окна браузера и проверяем, что меню и контент правильно перестраиваются. Отмечаем отсутствие горизонтального скролла и адекватную читабельность интерфейса на разных разрешениях.

Проведённые тесты показывают, что заявленный функционал работает стабильно, отсутствуют критические ошибки. Фильтрация, модальные окна, выбор мест и сохранение данных проходят проверки по регрессионным критериям.

  

# Раздел 3. Результаты работы и перспективы развития

## 3.1 Адаптивность и UX

Реализованный интерфейс спроектирован с учётом адаптивного дизайна. Для разных разрешений экрана применены медиазапросы: меню навигации при малых ширинах сжимается или перекладывается в гамбургер (см. SCSS-модуль _header.scss), карточки фильмов выстраиваются в одну колонку на мобильных и в две-три колонки на десктопах. Такой **mobile-first подход** обеспечивает удобство использования на смартфонах и планшетах.

С точки зрения UX реализованы удобные решения:

- **Слайдер на главной странице** привлекает внимание к афише, а навигация по нему (стрелки и индикаторы) встроена из **itc-slider**.
- **Простота интерфейса выбора кинотеатра**: карточки снабжены изображением и адресом, клик по ним интуитивно понятен.
- **Фильтрация фильмов по жанрам** улучшает поиск по контенту. Визуальные элементы (значки жанров genre-badge) позволяют быстро ориентироваться.
- **Выбор мест**: явные клеточки зала с разделением на занятые/свободные (.occupied/пустое) и индикацией выбранных (.selected). Подсказки типа номер ряда и количество мест в алерте после брони помогают пользователю подтвердить выбор.
- **Темы оформления** (светлая/тёмная) добавляют персонализации интерфейса, а переключатель «🌙» в шапке доступен с любой страницы.

## 3.2 Возможности масштабирования

Разработанное решение легко расширяемо и модифицируемо:

- **Добавление фильмов/кинотеатров**: данные хранятся во внешних JSON. Чтобы расширить ассортимент, нужно лишь обновить data.json или cinemas.json – логику кода менять не придётся.
- **Новые сеансы и залы**: структура данных (movie.sessions – массив времен) допускает любое количество сеансов. При усложнении (несколько залов, даты) достаточно изменить форму JSON и немного скорректировать script.js.
- **Улучшение UI**: можно подключать другие модули, например систему оплаты (что упомянуто в проектных идеях) – для этого оставлены точки расширения (например, модальное окно «Оплата»).
- **Тема и доступность**: сейчас реализованы базовые контрасты для тёмной темы, но при необходимости можно расширить поддержку (например, увеличение шрифтов, озвучивание модалок).

Таким образом, архитектура проекта позволяет постепенно добавлять функционал без полной переработки кода. Использование модульной SCSS и декомпозированных JS-функций облегчает поддержку. В частности, для локального хранилища легко переключиться на серверную базу – нужно только подменить функции загрузки/сохранения данных, а интерфейс останется прежним.

function renderSeats() {

    const seatsGrid = document.getElementById('seats-grid');

    seatsGrid.innerHTML = '';

    for (let row = 0; row < 8; row++) {

        for (let num = 0; num < 8; num++) {

            const seat = document.createElement('div');

            seat.className = 'seat';

            const seatId = `${row}-${num}`;

            seat.dataset.id = seatId;

            // Если место забронировано ранее, отмечаем как occupied

            const isOccupied = state.bookings.some(b =>

                b.movie === state.selectedMovie.title

                && b.session === state.selectedSession

                && b.seats.includes(seatId)

            );

            if (isOccupied) seat.classList.add('occupied');

            // Обработчик для выбора/снятия выбора

            seat.addEventListener('click', () => toggleSeatSelection(seat));

            seatsGrid.appendChild(seat);

        }

    }

    updateBookingButton();

}

function bookSeats() {

    const booking = {

        movie: state.selectedMovie.title,

        session: state.selectedSession,

        seats: [...state.selectedSeats],

        date: new Date().toLocaleString(),

        genre: state.selectedMovie.genre

    };

    state.bookings.push(booking);

    localStorage.setItem('bookings', JSON.stringify(state.bookings));  // Сохраняем бронирования

    alert(`Бронь успешна!\nФильм: ${booking.movie}\nВремя: ${booking.session}\nМеста: ${booking.seats.length} шт.`);

    state.selectedSeats = [];

    renderSeats(); // Обновляем сетку после брони

}
